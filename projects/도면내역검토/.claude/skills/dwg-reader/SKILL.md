# DWG/DXF 도면 분석 스킬

## 준비 (최초 1회)
- Python 패키지: `pip install ezdxf openpyxl`
- DWG 변환기: ODA File Converter (무료) 설치. 기본 경로(`C:\Program Files\ODA\...`)는 자동 탐지되고, 다른 경로면 환경변수 `ODA_CONVERTER`에 exe 경로 지정.
- 패키지가 없으면 사용자에게 알린 뒤 설치부터 진행.

## 작업 순서

### 1. DWG면 DXF로 변환
```
python "<스킬폴더>/scripts/convert_dwg.py" "<파일.dwg 또는 폴더>" --out "<출력폴더>"
```
- 기본 출력은 ACAD2018 DXF(UTF-8)라서 한글이 안전함.
- 반환코드 2(변환기 없음)면: 사용자에게 ODA 설치 안내 또는 AutoCAD/TrueView에서 DXF로 직접 저장해 달라고 요청. 코워크처럼 격리된 환경에서는 윈도우 ODA를 호출하지 못할 수 있으므로 이 경우 DXF 업로드를 요청.
- 이미 DXF면 이 단계 생략.

### 2. 분석
```
python "<스킬폴더>/scripts/analyze_dxf.py" "<도면.dxf>" --xlsx "<도면명>_분석.xlsx" [--map "<매핑.csv>"] [--nested]
```
- 표준출력 JSON 요약을 읽고 보고. 엑셀에는 요약, 블록수량, 블록속성, 레이어, 문자 시트가 생성됨.
- 한글 깨짐은 자동 감지 후 cp949로 재시도함(`encoding` 필드 확인). 그래도 깨지면 `--encoding cp949` 또는 `--encoding johab` 지정.
- `--nested`: 블록 안에 들어있는 블록(예: 실 단위 세트 안의 조명)까지 수량에 포함. 이중 집계 위험이 있으므로 사용자에게 어떤 기준인지 명시.
- `--map`: 블록 이름 → 품목명 매핑 CSV(`pattern,item`, 와일드카드 `*` 지원, 위에서부터 먼저 일치한 규칙 적용). 이 프로젝트에서는 `공통/품목매핑.csv`로 대조하므로 보통 생략. 사용자의 설계사무소 블록 규칙을 알게 되면 매핑 CSV를 갱신하자고 제안.

### 3. 보고 방식
비서가 먼저 도면을 보고 요약 보고하는 형식으로 정리:
1. 도면 개요: 파일명, 단위, 레이어 수, 블록 종류와 총 개수, 외부참조(xref) 여부
2. 기구 수량표: 품목(매핑 결과) / 블록명 / 수량 / 레이어
3. 주요 문자: 케이블 규격(HFIX, F-CV 등), 차단기 용량, 실명 등 의미 있는 것 위주
4. 레이어별 선 길이: 배선·배관 레이어로 보이는 것만, 단위 명시
5. 검토 의견: 이상해 보이는 점(미매핑 블록, 꺼진/동결 레이어에 있는 기구, xref로 빠진 내용, 깨진 문자)

## 한계 (보고 시 반드시 고지)
- 선 길이는 모델공간의 선 객체 실측 길이 합계. 도면 축척, 입상·입하 수직 길이, 여장은 반영 안 됨. 내역서 물량과 직접 비교하면 안 되고 참고치로만 사용.
- 블록 안에 그려진 선은 길이 합계에 포함 안 됨.
- 외부참조(xref) 도면 내용은 포함 안 됨. 원본 xref 파일을 따로 분석해야 함.
- 블록이 아닌 선·원으로 그린 기구는 수량에 안 잡힘.
- 동적 블록(`*U` 이름)은 원래 이름 추적을 시도하지만 실패할 수 있음.
- 페이퍼공간(레이아웃)의 도곽·표는 분석 대상이 아님.
